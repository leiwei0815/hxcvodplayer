**你的视频使用的就是格式 8：`AV_SAMPLE_FMT_FLTP` (float planar)**

## 修复方案

### 完整格式转换支持

现在支持所有常见的 FFmpeg 音频格式，统一转换为 iOS AudioQueue 需要的 **S16 交织格式**。

#### 转换逻辑

**1. Planar (平面) 格式 → Interleaved (交织)**

```
输入 (FLTP, 双声道):
  Channel 0: [f0, f1, f2, f3, ...]
  Channel 1: [f0, f1, f2, f3, ...]

输出 (S16 交织):
  [s0_L, s0_R, s1_L, s1_R, s2_L, s2_R, ...]
```

**2. Float → Int16 转换**

```cpp
float sample = src[i];
if (sample > 1.0f) sample = 1.0f;   // 防止溢出
if (sample < -1.0f) sample = -1.0f;
int16_t output = (int16_t)(sample * 32767.0f);
```

### 实现代码

**`src/core/player_core_c_bridge.cpp`**

```cpp
case AV_SAMPLE_FMT_FLTP:  // float, planar (平面)
{
    for (int i = 0; i < samples; i++) {
        for (int ch = 0; ch < channels; ch++) {
            float* src = (float*)frame->data[ch];
            float sample = src[i];
            if (sample > 1.0f) sample = 1.0f;
            if (sample < -1.0f) sample = -1.0f;
            dst[i * channels + ch] = (int16_t)(sample * 32767.0f);
        }
    }
    break;
}
```

### 性能考虑

**1. 格式优先级**

| 格式 | 速度 | 质量 | 场景 |
|------|------|------|------|
| `S16` | 最快 | 好 | 游戏、实时通信 |
| `S16P` | 快 | 好 | 编辑软件 |
| `FLTP` | 中等 | 最好 | 音乐、视频 ⭐ |
| `FLT` | 中等 | 最好 | 专业音频 |

**2. 转换开销**

- **S16/S16P**: 无需转换或简单重排，~0.1ms/帧
- **FLTP/FLT**: 需要浮点乘法，~0.3ms/帧
- **S32/S32P**: 需要位移操作，~0.2ms/帧

**3. 典型场景**

```
YouTube/B站视频: FLTP (AAC/Opus 解码输出)
音乐文件: FLTP (MP3/AAC 解码输出)
游戏音频: S16 (直接输出)
专业编辑: FLT/FLTP (最高精度)
```

## 常见问题

### Q1: 为什么要转换为 S16？

**A:** iOS AudioQueue 最高效支持 S16 格式：
- 硬件加速支持
- 低 CPU 开销
- 兼容性最好

### Q2: Float 转 Int16 会损失精度吗？

**A:** 会有轻微损失，但人耳无法察觉：
- Float 动态范围：~144 dB
- Int16 动态范围：~96 dB
- 人耳辨别极限：~60 dB
- **结论：质量足够**

### Q3: 为什么视频常用 FLTP？

**A:** 
- AAC/Opus 解码器输出为 FLTP
- 浮点计算精度更高
- 适合多级处理（滤镜、混音等）

### Q4: 如何优化性能？

**A:** 
1. 使用 SIMD 优化（Neon on ARM）
2. 批量转换多个采样
3. 使用 SwrContext 硬件加速重采样
