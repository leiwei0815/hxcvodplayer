# macOS 播放器视频无画面问题 - 最终修复

## 🎯 问题根源

通过详细的日志诊断，发现了问题的根本原因：

### 症状
- ✅ 音频播放正常
- ❌ 视频无画面
- ✅ 视频帧在渲染（有 `[视频] 渲染帧` 日志）
- ❌ 视频帧卡在第一帧（PTS 一直是 0.07）

### 关键日志
```
[INFO] 启动音频线程...
[INFO] 音频线程已启动
[INFO] 音频线程已结束  ← ❌ 立即结束！
[INFO] 视频解码器已恢复，开始解码...
[视频] 渲染帧 - PTS: 0.07, 主时钟: 0.00, 尺寸: 1920x1080
[视频] 渲染帧 - PTS: 0.07, 主时钟: 0.00, 尺寸: 1920x1080  ← 卡住
```

### 根本原因

**音频线程和 AudioQueue 回调冲突！**

在 macOS 原生平台上：
1. ✅ 使用 `AudioQueue` 来播放音频
2. ✅ `AudioQueue` 通过回调 → `fillAudioBuffer` → `player_core_get_audio_data` 获取音频数据
3. ❌ 同时还启动了 `audio_thread` 线程来解码音频
4. ❌ **两者竞争消费音频帧队列**，导致混乱
5. ❌ 音频线程快速消费完所有帧后退出
6. ❌ AudioQueue 回调无法获取数据
7. ❌ 主时钟（音频时钟）不更新
8. ❌ 视频等待音频同步，卡在第一帧

## 🔧 修复方案

### 修改文件：`src/core/hxc_player_core.cpp`

#### 修复前（错误）
```cpp
#ifndef NO_SDL
        LOG_INFO("iOS 平台，音频由上层渲染");
#endif
        
// ❌ 无条件启动音频线程
LOG_INFO("启动音频线程...");

#ifndef NO_SDL
        SDL_PauseAudioDevice(audio_dev_, 0);
        LOG_INFO("音频设备已启动");

```

#### 修复后（正确）
```cpp
        LOG_INFO("iOS 平台，音频由上层渲染");
#endif

        // ✅ 只在 SDL 平台启动音频线程
        LOG_INFO("启动音频线程...");
        audio_thread_ = std::thread(&PlayerCore::audio_thread, this);
        LOG_INFO("音频线程已启动");
        
        SDL_PauseAudioDevice(audio_dev_, 0);
        LOG_INFO("音频设备已启动");
#else
        // ✅ 原生平台不需要音频线程
        LOG_INFO("原生平台：音频由 AudioQueue 回调驱动，无需音频线程");
#endif
```

## 📊 音频架构对比

### SDL 平台（Qt 桌面版）
```
audio_thread（解码线程）
    ↓
解码音频帧 → audio_queue（内存队列）
    ↓
SDL_AudioCallback（SDL 回调）
    ↓
从 audio_queue 取数据 → SDL 音频设备
```

### 原生平台（iOS/macOS Cocoa）
```
AudioQueue 回调
    ↓
fillAudioBuffer
    ↓
player_core_get_audio_data（C 桥接）
    ↓
实时解码（按需解码）→ AudioQueue 播放
```

**关键区别：**
- **SDL**: 需要 `audio_thread` **提前解码**到队列
- **原生**: AudioQueue 回调**按需解码**，不需要线程

## 技术要点

### NO_SDL 宏的正确使用

```cpp
#ifndef NO_SDL
    // SDL 平台特定代码
    // - 启动音频线程
    // - 初始化 SDL 音频设备
#else
    // 原生平台特定代码
    // - 使用 AudioQueue/AVAudioEngine
    // - 回调驱动，无需线程
#endif
```

### 音频解码的两种模式

**1. 预解码模式（SDL）**
- 使用独立线程提前解码
- 解码结果存入内存队列
- SDL 回调从队列取数据
- 优点：解耦，SDL 回调简单
- 缺点：需要额外线程和内存

**2. 按需解码模式（原生）**
- 没有独立解码线程
- AudioQueue 回调时实时解码
- 通过 C 桥接调用核心解码
- 优点：节省线程和内存
- 缺点：回调中解码，需要快速
