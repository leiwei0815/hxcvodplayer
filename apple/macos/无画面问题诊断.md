# macOS 播放器无画面问题诊断

## 架构说明

### 视频渲染流程

```
CVDisplayLink (60 FPS)
    ↓
renderVideoFrame (HXCPlayerControl)
    ↓
displayVideoFrameData
    ↓
创建 CVPixelBuffer
    ↓
创建 CMSampleBuffer
    ↓
enqueueSampleBuffer → AVSampleBufferDisplayLayer
    ↓
HXCPlayerView.layer (显示)
```

### HXCPlayerView 的职责

`HXCPlayerView` **不负责渲染**，它只负责：
1. ✅ 提供一个 layer-backed view
2. ✅ 将 `HXCPlayerControl.videoLayer` 添加为子层
3. ✅ 管理 videoLayer 的 frame（大小和位置）

### HXCPlayerControl 的职责

`HXCPlayerControl` 负责实际的视频渲染：
1. ✅ 从核心获取视频帧数据
2. ✅ 转换为 CVPixelBuffer
3. ✅ 创建 CMSampleBuffer
4. ✅ 提交到 AVSampleBufferDisplayLayer

## 问题诊断清单

### 1. 检查日志输出

运行应用后，查看控制台日志，应该看到：

```
[播放器] 初始化 HXCPlayerControl...
✅ VideoLayer 创建成功 - Frame: ...
[PlayerView] 设置播放器 - 添加 VideoLayer, bounds: ...
✅ VideoLayer 已添加到视图, frame: ...
[音频] 初始化 AudioQueue - 采样率: 48000, 通道: 2
✅ AudioQueue 初始化完成 - 缓冲区大小: 16384 bytes
[视频] 启动 CVDisplayLink...
✅ CVDisplayLink 启动成功
[视频] 渲染帧 - PTS: 0.00, 主时钟: 0.00, 尺寸: 1920x1080
```

#### 关键日志检查

**如果看到：**
- ❌ `❌ VideoLayer 为空！` → videoLayer 未正确创建
- ❌ `❌ CVDisplayLink 创建失败` → 显示链接创建失败
- ❌ `❌ 创建 CVPixelBuffer 失败` → 像素缓冲区创建失败
- ❌ `❌ VideoLayer 渲染失败` → layer 渲染错误

**如果没有看到：**
- ❌ `[视频] 渲染帧 - PTS: ...` → CVDisplayLink 未调用或没有视频帧

### 2. 视频帧数据检查

可能的原因：
- 视频解码失败
- 视频队列为空
- 视频格式不支持

### 3. AVSampleBufferDisplayLayer 状态检查

在 `displayVideoFrameData` 中已经添加了状态检查：
```objective-c
if (self->_videoLayer.status == AVQueuedSampleBufferRenderingStatusFailed) {
    NSLog(@"❌ VideoLayer 渲染失败: %@", self->_videoLayer.error);
    [self->_videoLayer flush];
}
```

如果看到这个日志，说明 layer 渲染失败。

### 4. 时间基准检查

确认 controlTimebase 已正确设置：
```objective-c
CMTimebaseRef controlTimebase;
CMTimebaseCreateWithSourceClock(...);
_videoLayer.controlTimebase = controlTimebase;
CMTimebaseSetRate(_videoLayer.controlTimebase, 1.0);
```

## 调试步骤

### 步骤 1: 检查基本日志

运行应用，查看是否有错误日志：
- 查看 Xcode Console
- 搜索 "❌" 或 "失败"

### 步骤 2: 确认 CVDisplayLink 运行

查看是否有 `[视频] 渲染帧` 日志：
- **有日志** → CVDisplayLink 正常运行，继续下一步
- **无日志** → CVDisplayLink 未启动或回调未执行

### 步骤 3: 检查视频帧获取

在 `renderVideoFrame` 开始处添加日志：
```objective-c
NSLog(@"[DEBUG] renderVideoFrame 被调用");
```

如果看到这个日志但没有 "渲染帧" 日志，说明：
- `player_core_get_video_frame` 返回错误
- 视频队列为空

### 步骤 4: 检查视频文件

确保：
- 视频文件有视频轨道（不是纯音频）
- 视频格式被 FFmpeg 支持
- 文件路径正确

### 步骤 5: 检查 View 层级

在 Xcode 中：
1. 运行应用
2. 点击 `Debug View Hierarchy` (⌘⇧D)
3. 查看 `HXCPlayerView` 是否有 `AVSampleBufferDisplayLayer` 子层
4. 查看 layer 的 bounds 和 frame 是否正确

## 常见问题和解决方案

### 问题 1: 看到日志但无画面

**症状：**
```
✅ CVDisplayLink 启动成功
[视频] 渲染帧 - PTS: 0.00, 主时钟: 0.00, 尺寸: 1920x1080
```
但是没有画面。

**可能原因：**
1. videoLayer 未添加到视图
2. videoLayer 的 frame 为 0
3. videoLayer 被遮挡

**解决方法：**
- 检查 `[PlayerView] 设置播放器` 日志
- 确认 videoLayer.frame 不为空
- 使用 View Hierarchy 调试

### 问题 2: 没有 "渲染帧" 日志

**症状：**
CVDisplayLink 启动成功，但没有渲染日志。

**可能原因：**
1. 视频队列为空（解码未启动）
2. `player_core_get_video_frame` 返回错误
3. 文件没有视频轨道

**解决方法：**
- 检查底层日志是否有视频解码成功的信息
- 尝试播放其他视频文件
- 在 `player_core_get_video_frame` 调用前后添加日志

### 问题 3: VideoLayer 渲染失败

**症状：**
```
❌ VideoLayer 渲染失败: Error Domain=...
```

**可能原因：**
1. 像素格式不支持
2. sampleBuffer 创建失败
3. timebase 设置错误

**解决方法：**
- 检查 CVPixelBuffer 创建是否成功
- 确认使用 NV12 格式 (kCVPixelFormatType_420YpCbCr8BiPlanarVideoRange)
- 验证 timebase 设置

## 验证视频文件

### 使用 FFmpeg 检查

```bash
ffmpeg -i your_video.mp4 2>&1 | grep Video
```

应该看到类似：
```
Stream #0:0: Video: h264, yuv420p, 1920x1080, 25 fps
```

### 使用 FFplay 验证

```bash
ffplay your_video.mp4
```

如果 ffplay 可以播放，说明文件格式正常。

## 下一步

根据日志输出，可以确定问题出在哪一步：

1. **VideoLayer 未创建** → 检查 init 方法
2. **CVDisplayLink 未启动** → 检查 startDisplayLink
3. **没有视频帧** → 检查核心解码逻辑
4. **有帧但不显示** → 检查 displayVideoFrameData
5. **layer 状态失败** → 检查 AVSampleBufferDisplayLayer 配置
